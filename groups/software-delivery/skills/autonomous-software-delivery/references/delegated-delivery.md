# Subagent-driven delivery

Requires a host with permission to spawn subagents that can access the target workspace. The coordinating agent owns the plan, checkpoint, and delivery endpoint. Keep the checkpoint in the plan or the project's existing work record. If neither is writable, use a workspace note and report its location for resumption.

1. **Prepare the slice.** Use the request or plan to identify its acceptance checks, dependencies, and write scope. Record a baseline that distinguishes this slice from preceding slices and existing local edits. Work in dependency order and give one implementer at a time write access to a shared workspace. If resuming, reconcile the checkpoint with the working tree and any pending agent work before dispatching.
2. **Delegate implementation.** Give a fresh subagent the slice brief, acceptance checks, applicable constraints, workspace, baseline, and write scope. Ask it to implement and test the slice using `implement-delivery-slice` if installed. Request the exact candidate revision or patch, checks run and outcomes, and unresolved concerns. Keep review, coordination, and external delivery actions with the coordinator.
3. **Choose the review point.** Honor any required independent review. For a low-risk slice with passing checks that exercise its full contract, the coordinator can verify the slice and defer independent review to integration. Record that decision and the checks run. Review the slice before dependent work when its failure would invalidate later slices, its contract is uncertain, or per-slice review is required. For an independent slice review, give a separate, fresh reviewer inspection and verification duties. Keep candidate edits with the implementer. Provide the original brief and acceptance checks, applicable constraints, baseline-to-candidate diff or reproducible revision range, and test evidence. Ask for separate verdicts on acceptance and code quality, using `verify-delivery-change` if installed. The reviewer should report concrete findings with the affected location or check, expected behavior, and observed behavior. A slice passes when its material criteria are verified and its blocking findings are resolved.
4. **Resolve findings and record progress.** Send confirmed blocking findings back to the implementer and have the reviewer verify each revised candidate. Use two fix-and-review rounds as a default budget. If the budget runs out, diagnose the remaining blocker and change the approach if a viable fix is available. Keep the slice open while blocking findings remain and continue work that does not depend on it. Update the delivery checkpoint with the candidate, verdicts, open findings, and next action before advancing.
5. **Review the integrated change.** Give a fresh reviewer the original request, full candidate diff against the delivery baseline, and slice evidence. Check cross-slice behavior, regressions, and coverage of the original acceptance criteria. Resolve blocking findings and recheck the integrated candidate before proceeding to the remaining endpoint checks.

If delegation becomes unavailable during the run, reconcile the checkpoint with the workspace before continuing directly. Record any review that still needs independent verification.
